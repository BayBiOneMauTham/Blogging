What are the “tech talks”?

August 7, 2024 12 min read Your Name

Please view the other part of this series here for more context

What are the “tech talks”?

Speak tech or Understanding tech, in this case, can be considered the following:

  • How does programming language work to code some lines

  • The architecture of a technical tool (Type, component of a tech tool, how the component interacts…)

  • Cloud computing - How it works

  • Data

Ok so that would be the basis, there are some keywords that you would likely see in day-to-day work like APIs, Server, Tenant, HTTP/HTTPS, microservice, etc that will also be included in this blog, and yes, everything will be from a non-tech POV. So please do note if anything isn’t right.

Why the urgency?

PM or other non-tech roles are there for a reason, they fill in the blanks of the tech sector to make things run smoothly. They called non-tech roles for a reason, they don’t need to have a deep understanding of tech, but as I stated and will say it again.

“If you work in the tech world, regardless of the position, not knowing tech is a huge disadvantage”

During my time working for multiple SAAS businesses I encounter some situations:

  • Having a hard time chatting with Devs or other tech roles, and got pushed out of the conversation if you couldn’t contribute to the “tech talks”. This impacts work if a decision is passed without your understanding.

  • Feeling awkward when you can’t elaborate on the “why” of some tech decision when the developer isn’t there, as a Product Manager you should at least understand this.

  • Taking time to gain trust and get buy-in from stakeholders

  • Overestimation for simple work but can’t rebuttal since you don’t understand what others are saying.

From my POV, the key motivation when learning tech was I didn’t want to feel stupid in a room full of tech people, luckily I realized that just a couple of weeks into the PM job so I tried.

So if you like me, get some understanding ASAP or your job will be a nightmare.

Let’s get this started.

Basic terminologies

At least for me, if you catch me as an Interviewer, I would consider you a very weak candidate if you can’t answer the following

Data type

Data is information stored on the machine, type is how they are stored, the following are the most basic

Network

To understand how this works, you should understand the basis of a network system, LAN, WAN, and the Internet.

This is how our world is connected and how you can read this at your home now.

IP Address: Unique address for your device on a network, to know sending what to whom.

LAN (Local Area Network): Connects devices within a limited area.

WAN (Wide Area Network): Connects devices over large geographical areas.

Internet: Global network connecting millions of private, and public networks.

Server

Some hardware that stores and might allow you to get data from there, a PC can be a server, now get 10 PCs, then remove all the screens, and buttons, also, strip the plastic covers. Stack everything on top of each other and plug the cable from other computers or servers.

⇒ You would likely get something closer to an actual server.

Library - Framework - Programming language

A library is a collection of resources used by computer programs, often for software development.

The framework is larger than a library, a library is just a bunch of resources used on demand, while the framework is first chosen to dictate the work.

And a programming language tells the computer what it should do. Every programming language has a syntax and a particular set of rules, which need to be followed every time the code is written.

A software framework is built on top of a programming language.

SDK

A software development kit (SDK) is a set of tools provided by the manufacturer of (usually) a hardware platform, operating system (OS), or programming language.

API

API is the middleman that takes a request from a client to Server-DB and returns the thing to you

Example below in the cloud computing part

Compiler

A compiler is a program that translates code written in a high-level programming language into machine code (binary) or an intermediate form such as bytecode.

  • What are those will be explained in the code classification part below

This translation is done before the program is executed.

Some common types of Applications

These can be overlapped, for example, a mobile app built specifically for IOS is classified as both a Mobile and Native app

  • Native apps: Created for one specific platform or operating system → IOS, Android

  • Mobile app: Created for mobile usage

  • Desktop Apps: Software programs run on personal computers, laptops, or desktop machines.

Cloud computing

Most of the new tech tools are now built on the Cloud, they can have local or on-prem versions but if you want to scale this is the way.

Cloud Computing architecture consists of mainly coupled essential components and sub-components for seamless computing operations. These components are

  • Front-end Platform-User Interface

  • Back-end Platform- Cloud Service Provider

Front-end is the menu you see and interact with in a restaurant, and the back end is the Chief that cooks at that back.

  • API is the waiter that goes back and forth sometimes depending on the system.

To understand cloud computing we must delve into the architecture, and how we come to this from the Personal Computer at your home.

Your home setting

Okay so let’s get back to the whole LAN, WAN thing.

Do you remember when you were a kid and you could play video games with someone who had a computer and sat right next to you?

It worked since the two computers were connected, by a cable. Now imagine 10 computers connected to a centralized server, they can then “Speak” to each other and transfer data back and forth.

Imagine connecting 100 servers like that into a giant server and you get a really big local (Not so local anymore) internet system.

What would happen on that Giant server?

Virtualize deployment

Remember I told you above that a server is a bunch of stripped-down PCs racking up on top of each other? It can be a dozen computing resources massed into one big machine. For the Giant server, it can be much bigger.

Because of that, most of the time, it would be too big to use at once. E.g if you want to open a document, you won’t likely take every resource on a Server to do so.

So you would need to split that hardware into multiple smaller machines to be used. This would need to be flexible and adaptable depending on your needs. This is when Virtualized deployment steps in.

Virtual machines (VM) are isolated and have a security barrier, each has its own Operating System with dedicated amounts of CPU, memory, and storage that are "borrowed" from a physical host computer (PC, server).

VM is a “Hosting” mechanism. It provides a virtualized environment that mimics a physical computer. It’s one of the ways to Host and Cloud hosting leverages a network of virtual and physical servers to host websites, applications, and other services.

So how is that relevant to the app you are using?

Every Cloud application (Maybe most?) uses the Back-end that way.

The application or the data you interact with isn’t on the machine or the browser (Can be on the browser that is enough for now). You get everything transferred from far away (called the “Cloud”) to your computer, phone, or other IoT devices.

So why can’t you access other data if everything is on this “cloud”?

There are multiple things related to this but the most simple is the concept of “tenant”

Tenant is a Group with shared access and isolated data within an application.

A VM can host a multi-tenant, where each tenant has its logical separation within the application. This allows multiple organizations or user groups to use the same application instance while keeping their data and configurations separate.

Single tenant is similar but splits the application also.

If you aren’t added to a tenant, you can’t access the tenant.

Coding and programming language

You just can’t get enough? Not it comes to the hard part. A system has 2 key components, Front and Back-end, so is code

Frontend - Code that is executed inside the browser, or markup which is interpreted while rendering a page.

  • HTML provides the basic structure of sites, which is enhanced and modified by other technologies like CSS and JavaScript.

  • CSS is used to control presentation, formatting, and layout.

  • JavaScript is used to control the behavior of different elements.

Backend - Receives requests and prepares data which is transmitted back to the user’s browser. Backend code is built to be running on a server and it’s never running on the user’s machine.

  • Java, Python, C++, C# are some of the prominent BE languages

Programming Language Classification

There are, of course, better classifications of languages based on how they work, naming some:

  • Procedural Programming Language - Executes a sequence of instructions in order.

    • Example: C

  • Object-Oriented Programming Language (OOP) - Organizes code into objects with properties and behaviors.

    • Example: Java

  • Markup Language - Uses tags to define and format text documents.

    • Example: HTML

  • Query Language - Used to make queries in databases and information systems for data.

    • Example: SQL

Apart from that languages can be classified based on how close they are to the hardware, usually the closer they are, the faster they run and the harder to understand.

  • High-level languages are closer to human language - Python, JavaScript

  • Assembly languages are C, C++.

  • Machine language is where it begins to turn crazy hard, they are Binary code - 01010101.

  • Hardware is the physical thing that you can hold like a baby, maybe a robot baby.

Programming Language Characteristic

Taken from https://www.geeksforgeeks.org/introduction-to-programming-languages/ with some add-on from myself

A programming language is a set of instructions and syntax used to create software programs. Some of the key features of programming languages include:

  1. Syntax: The specific rules and structure used to write code in a programming language.

  2. Data Types: The type of values that can be stored in a program, such as numbers, strings, and booleans.

  3. Variables: Named memory locations that can store values.

  4. Operators: Symbols used to perform operations on values, such as addition, subtraction, and comparison.

  5. Control Structures: Statements used to control the flow of a program, such as if-else statements, loops, and function calls.

  6. Libraries and Frameworks: Collections of pre-written code that can be used to perform common tasks and speed up development.

  7. Paradigms: The programming style or philosophy used in the language, such as procedural, object-oriented, or functional.

And the little thing in life

  • CRUD refers to the four functions considered necessary to implement a persistent storage application: create, read, update, and deleted

  • The Hypertext Transfer Protocol (HTTP) is the foundation of the World Wide Web and is used to load webpages using hypertext links

    • An HTTP method, sometimes referred to as an HTTP verb, indicates the action that the HTTP request expects from the queried server. In a REST environment, CRUD often corresponds to the HTTP methods POST, GET, PUT, and DELETE.

    • HTTPS: HTTPS is HTTP with encryption and verification. The only difference between the two protocols is that HTTPS uses TLS (SSL) to encrypt normal HTTP requests and responses. As a result, HTTPS is far more secure than HTTP.

  • RESTful APIs: RESTful APIs adhere to REST principles, using HTTP methods for CRUD operations on resources, identified by URLs, and typically return data in JSON or XML format.

    • JSON or JavaScript Object Notation is a text format for storing and transporting data

    • XML or eXtensible Markup Language is a markup language much like HTML and was designed to store and transport data.

  • Event Bus/Messaging Platforms: Event buses and messaging platforms facilitate asynchronous communication between services via message passing, enabling decoupled, scalable systems.

  • SQL and NoSQL Databases:

    • SQL databases use structured schemas and SQL queries for relational data (e.g., MySQL).

    • NoSQL databases provide flexible, schema-less storage for unstructured data (e.g., MongoDB).

  • Cloud Services (AWS as an example): AWS offers scalable cloud computing resources, including compute (EC2), storage (S3), databases (RDS), and various managed services, enabling on-demand infrastructure and application deployment.

  • Monolith is a software architecture, where you mix everything into one single pile that works fast, easy to build but hardly scales.

    • Microservices are when you split that mess into multiple smaller messes that can be interconnected and scaled.
